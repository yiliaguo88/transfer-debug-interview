# Candidate Brief — Transfer Debug Interview

## 背景
线上偶尔出现：扣款/入账不一致，请查明原因

## 任务
1. 先理解系统和数据流。
2. 先提出 hypotheses，不要直接大改代码。
3. 找到尽可能多的问题。
4. 修复关键问题。
5. 用测试、日志或可重复实验给出证据。
6. 说明剩余风险。
7.  需要实现复式记账一致性检查，找出不匹配的 Transfer



请编写  SQL，统计 2026 年 9 月 28 日（含）至 2026 年 10 月 28 日（不含）每个账户的成功转账情况，输出：

| 输出字段 | 含义 |
|---|---|
| account_id | 账户 ID |
| account_name | 账户名称 |
| outgoing_count | 成功转出笔数 |
| outgoing_amount | 成功转出总金额 |
| incoming_count | 成功转入笔数 |
| incoming_amount | 成功转入总金额 |
| net_inflow | 净流入金额，即转入总金额减去转出总金额 |
| avg_outgoing_amount | 平均每笔成功转出金额 |

具体要求：

1. 仅统计 `status = 'SUCCESS'` 的转账。
2. 保留所有账户，没有转账的账户统计指标均显示为 `0`。
3. 平均转出金额保留两位小数。
4. 按净流入金额降序排列；相同时按账户 ID 升序排列。
5. 避免同一账户的多笔转入与多笔转出关联后，行数相乘导致统计金额重复。
